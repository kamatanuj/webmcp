Findings — the crossover landed

  • DOM cost scales with the catalog: total action bytes 91,323 → 237,183 (+160%) when the catalog grew 5×; every task re-drags the whole catalog (~29.7KB each, flat across tasks).
  • MCP cost scales with the task: 40,477 → 49,037 (+21%). search_products returns only the matching slice (4.3–8.6KB/task).
  • MCP now wins every economy metric: −79% action bytes vs DOM and −42% LLM input tokens. At 30 products it already won bytes (−56%); at 150 the token side crossed too.
  • Both sides 8/8 correct, 16/16 identical picks — same answers, wildly different cost curves.
  • DOM keeps raw-speed lead per task on small lookups but pays 5× the data; MCP time dropped 30→150 (74.3 → 57.3s) since richer filters mean fewer tool round-trips.
  • Projection: the gap widens super-linearly for DOM at 500+ products (31KB → ~100KB+ per task), while MCP stays task-bound. Confirms the paper's thesis at real-browser fidelity.
