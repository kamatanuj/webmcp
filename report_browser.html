Findings

  • MCP cuts per-task site data ~56% in real-browser execution (40KB vs 91KB over 8 tasks) — structured tool responses instead of dragging the whole catalog through the context.
  • DOM path is cheaper for the LLM: one catalog read covers the task (1–2 LLM calls); MCP needs 2–4 calls and re-sends tool schemas each turn — ~2.6× input tokens.
  • DOM path is faster (25s vs 74s) — fewer round-trips. Both complete all tasks correctly.
  • Deterministic: all 16 picks identical across both runs at temperature 0; action bytes vary ≤3%.
  • Trade-off: MCP = context economy on the wire; DOM = fewer turns, cheaper tokens, faster. On a catalog this small DOM wins on cost/speed; MCP wins as data volume grows.
